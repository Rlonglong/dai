# 12 · 疑難排解

> 兩套系統的症狀對照表。先用症狀找到那一列，再看「怎麼查」。

---

## 1. 先確認服務本身活著

```bash
# D-Track（VM3）
cd /run/media/root/D/deploy
docker compose ps dtrack-server dtrack-frontend
curl -sk https://dtrack.dai.post.gov.tw/api/version          # 應回 JSON 含 version
curl -sk https://dtrack.dai.post.gov.tw/api/v1/oidc/available # 應回 true

# Superset（VM5）
cd /run/media/root/D/deploy
docker compose ps superset
curl -sk -o /dev/null -w "%{http_code}\n" https://superset.dai.post.gov.tw   # 302
```

服務沒起來就先看 log：

```bash
docker compose logs --tail 200 dtrack-server
docker compose logs --tail 200 superset
```

## 2. Dependency-Track

| 症狀 | 原因 | 怎麼處理 |
|---|---|---|
| `dtrack-server` 一直 unhealthy | API server 啟動慢（JVM） | healthcheck `start_period=120s`，等足時間；`docker logs dtrack-server` 確認有無 exception |
| OIDC available 回 `false` | JVM TrustStore 缺自簽 CA | 確認映像為 `dai/dt_apiserver:v2.1` 以上；或手動 `keytool -import -cacerts` 後重啟（見部署手冊 Phase 3-4） |
| 網頁打得開但 SSO 按鈕不見 | 同上，OIDC 沒啟用 | 同上 |
| CI 上傳 SBOM 失敗（401） | API Key 被撤銷或打錯 | 重新產 Key，更新 GitLab Variable `DTRACK_API_KEY` |
| CI 報「查不到專案 UUID」 | API Key 少了 `PROJECT_CREATION_UPLOAD` | 補權限（見 [10](./10_D-Track_專案_API_Key_與擋門門檻.md#2-api-key)） |
| CI 報「等待 D-Track 分析逾時」 | 套件多、分析慢，或 server 有問題 | 先確認 server healthy；真的是慢就調高 `DTRACK_POLL_MAX` |
| 標了 Not Affected 但 pipeline 還是紅 | metrics 沒重算 | Refresh Metrics（見 [日常維運 · 04 · 第 5 節](../日常維運/04_弱掃紅燈與MR被卡住的解除流程.md#5--讓-d-track-重算最常卡住的一步)） |
| 標了例外還是紅，metrics 也刷新了 | 標在別的 project version 上 | 確認 job log 裡的 `專案名:版本`，到**那一個** version 標記 |
| 專案數量爆炸 | 每個分支都會建一個 version | 半年清一次舊分支的專案 |
| 弱點數字自己變多 | NVD/OSV 有新公告 | 正常現象，這正是每季弱掃存在的理由 |
| 容器重建後 CA 又不見了 | 手動 `keytool` 匯入不會持久 | 用 `Dockerfile.dt_apiserver` 重編映像 |

## 3. Superset

### 登入 / 權限

| 症狀 | 原因 | 怎麼處理 |
|---|---|---|
| 點 SSO 跳回登入頁、無錯誤訊息 | client secret 不符 | 比對 Keycloak client Credentials 與 `superset_config.py` |
| `redirect_uri_mismatch` | Keycloak 的 Valid redirect URIs 沒涵蓋 | 設成 `https://superset.dai.post.gov.tw/*` |
| 登入成功但畫面空白／沒有選單 | 沒拿到角色 | `Settings → List Users` 看實際 Roles；檢查 `AUTH_ROLES_MAPPING` |
| 昨天看得到今天看不到 | `AUTH_ROLES_SYNC_AT_LOGIN=True` 洗掉手動加的角色 | 把該角色加進 `AUTH_ROLES_MAPPING`（見 [11 · 第 3 節](./11_Superset_SSO與設定檔.md#3-角色怎麼對應)） |
| 使用者看不到某個 Dataset | Gamma 預設看不到任何資料 | 建自訂角色加 `datasource access`（見 [日常維運 · 02](../日常維運/02_Superset_資料庫連線與權限.md#3-權限模型)） |

### 資料 / 查詢

| 症狀 | 原因 | 怎麼處理 |
|---|---|---|
| 圖表數字沒更新 | 資料表本身沒更新 | 去 Dagster 看批次有沒有跑完 |
| 資料表有新資料但圖表還是舊的 | 快取 | 圖表 **⋮ → Force refresh**；或調 `CACHE_DEFAULT_TIMEOUT` |
| 查詢逾時 | 撈太多 / 缺索引 | 加日期條件；長期解是做彙總表，不是調大逾時 |
| 新資料庫 Test Connection 失敗 | 防火牆、DNS、帳密 | 見下方「連線排查順序」 |
| SQL Lab 選不到某個資料庫 | 沒勾 Expose in SQL Lab | Database Connections → 編輯 → Advanced |
| 可以下 UPDATE / DELETE | **Allow DML 被打開了** | ★立刻關掉★，並確認資料庫帳號是唯讀的 |

### 顯示

| 症狀 | 原因 | 怎麼處理 |
|---|---|---|
| 中文顯示成方框 | 容器內沒有中文字型 | 在映像檔加中文字型（例如 `fonts-noto-cjk`）後重建 |
| 匯出 CSV 中文亂碼 | Excel 預設編碼不是 UTF-8 | Excel「資料 → 從文字/CSV」匯入並選 UTF-8 |
| `docker exec superset ps aux` 說找不到指令 | Debian slim 映像沒有 `ps` | 改用 `docker exec superset sh -c "cat /proc/<pid>/cmdline"` |

### 連線排查順序

```bash
# 1. 容器解不解得到主機名稱
docker exec superset getent hosts <資料庫主機名稱>
#    解不到 → 請 IT 加進公司 DNS，或連線設定改填 IP
#    （VM5 的 dns: 被限定在公司 DNS，見部署手冊 Phase 2-1）

# 2. port 通不通
docker exec superset bash -c 'cat < /dev/null > /dev/tcp/<主機>/<port>' && echo OK
#    不通 → 防火牆要開 VM5 → 資料庫主機:port

# 3. 帳密對不對
#    用資料庫端的 client 直接測那組帳密

# 4. 驅動有沒有裝
docker exec superset python -c "import pyodbc; print(pyodbc.drivers())"
#    SQL Server 要看到 'ODBC Driver 18 for SQL Server'
```

## 4. 兩套系統共通

| 症狀 | 原因 | 怎麼處理 |
|---|---|---|
| 瀏覽器顯示憑證不受信任 | 使用者電腦沒匯入自簽 CA | 把 `GRCA3.crt` 匯入使用者電腦的信任清單 |
| 容器內呼叫 HTTPS 報 `certificate verify failed` | 容器的 trust store 沒有 CA | 見部署手冊 Phase 0-9 / 3-2 / 3-4 |
| 重開機後服務沒回來 | compose 少了 `restart: unless-stopped` | 補上該設定 |
| 改了設定沒生效 | 沒重啟容器 | `docker compose restart <服務>` |
