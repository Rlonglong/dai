# 00 · 兩套系統總覽

---

## 1. 它們在整套平台的哪裡

```
   開發人員改程式碼
        │
        ▼
   ┌──────────────────────────── VM3 ────────────────────────────┐
   │  GitLab ──MR──▶ CI pipeline                                 │
   │                    │                                        │
   │                    ├─ lint / test / gitleaks / bandit       │
   │                    │                                        │
   │                    └─ sca-dtrack ──SBOM──▶ Dependency-Track │
   │                                              │              │
   │                                   比對 NVD / OSV / GitHub    │
   │                                              │              │
   │                            Critical / High > 0 → pipeline 紅燈
   └─────────────────────────────────────────────────────────────┘
        │ 合併進 main
        ▼
   ┌──── VM4 ────┐         ┌──── VM1 ────┐
   │   Dagster   │──SSH──▶ │ BCP 清洗腳本 │
   │   + dbt     │         └─────────────┘
   └──────┬──────┘
          │ 產出名單 / 統計表（SQL Server、PostgreSQL）
          ▼
   ┌──────────────────────── VM5 ────────────────────────┐
   │  Keycloak（SSO）                                     │
   │  Superset ──連線──▶ 資料庫，做成圖表給業務單位看        │
   └──────────────────────────────────────────────────────┘
```

**一句話分工**：

| | Dependency-Track | Superset |
|---|---|---|
| 看的是 | **程式碼用了哪些套件** | **程式碼跑出來的資料** |
| 誰餵資料給它 | GitLab CI（每次推送 + 每季） | Dagster / dbt（每天批次） |
| 出事的樣子 | pipeline 紅燈，東西上不去 | 圖表沒更新、數字不對 |
| 主要使用者 | 維運人員、開發人員 | 業務單位 |

## 2. Dependency-Track 在做什麼

### 問題

我們自己寫的程式碼有 flake8 / bandit 在管，
但**真正的攻擊面大多在別人的程式碼裡**——
`cryptography`、`pandas`、`pymssql`、`numpy` 每一個都可能被公告 CVE。

### 做法

```
套件清單（requirements.txt 或映像檔裡實際裝的東西）
      │  cyclonedx-py
      ▼
   SBOM（bom.json）  = 「我用了哪些套件、哪個版本」的機器可讀清單
      │  上傳
      ▼
Dependency-Track
      │  比對 NVD / OSV / GitHub Advisory
      ▼
Critical / High / Medium / Low 各幾個
      │
Critical / High > 0 → pipeline 紅燈 → 合併不進 main → 上不了正式機
```

### 兩種掃描

| | 推送時 `sca-dtrack` | 每季 `sca-dtrack-quarterly` |
|---|---|---|
| 什麼時候跑 | MR / push / 合併 main | 排程（1/4/7/10 月 1 號 03:00）或手動 |
| 擋門標準 | **Critical + High** | **Critical + High + Medium** |
| artifacts 保留 | 1 週 | **1 年**（稽核用） |

**兩個門檻都不含作業系統層套件**（`glibc`、`libc-bin`…）——
那些由 CI 自動放行（[04 · 第 2 節](./日常維運/04_弱掃紅燈與MR被卡住的解除流程.md#2-作業系統層套件libc-那一類已經自動放行)）。

**為什麼推送掃過了還要每季再掃**：因為弱點資料庫每天在長，但你的程式碼沒有變。

```
2026-01-15  push cryptography==49.0.0 → 掃描 0 Critical ✅ 上線
2026-03-02  公告 CVE-2026-XXXXX，影響 cryptography <= 49.1
            ← 程式碼一行沒改，但它現在有一個 Critical
            ← 沒有任何 pipeline 會跑，沒有人會知道
2026-04-01  ★每季弱掃★ 用最新資料庫重掃 → 紅燈 → 有人去處理
```

> **日常敢擋到 High**，是因為 base image 的 OS 套件已經自動放行，
> 剩下的都是「我們自己選的套件」，數量可控。
> **每季多擋 Medium**：那一次專門用來清技術債，時間點固定、可以事先安排人力。
>
> 擋住之後怎麼過（升級／標記 Not Affected 寫理由／排期），見
> [04_弱掃紅燈與MR被卡住的解除流程](./日常維運/04_弱掃紅燈與MR被卡住的解除流程.md)。

### 兩個 repo 的 SBOM 來源不一樣

| repo | 來源 | 為什麼 |
|---|---|---|
| `bcp-scripts` | `requirements.txt` | VM1 有自己的 venv，套件清單就在 repo 裡 |
| `dagster-workspace` | **映像檔**（`DTRACK_IMAGE`） | 套件烘焙在 `dai/dagster` 映像檔裡，repo 沒有 requirements.txt |

`ci/build_sbom.sh` 會自動判斷。`dagster-workspace` 沒設 `DTRACK_IMAGE` 的話
**job 會直接失敗，而不是跳過**——因為只掃 repo 裡的檔案會掃出「零個套件」然後綠燈，
那是假的。**一個靜默跳過的資安掃描，比沒有掃描更危險。**

## 3. Superset 在做什麼

### 位置

Superset 是**唯讀的展示層**。它不產生資料、不改資料，
只是連到 Dagster / dbt 已經跑好的資料表，把它畫成圖。

```
Dagster + dbt 每天跑完
      ▼
資料表（詐欺名單、統計、對帳結果…）
      ▼
Superset Dataset（一張表 or 一段 SQL）
      ▼
Chart（圖表）
      ▼
Dashboard（一頁多張圖，給業務單位看的成品）
```

### 四個名詞

| 名詞 | 是什麼 | 誰建 |
|---|---|---|
| **Database** | 一組資料庫連線設定 | 管理員（見 [02](./日常維運/02_Superset_資料庫連線與權限.md)） |
| **Dataset** | 一張實體表，或一段 SQL 的結果（Virtual Dataset） | 開發人員 |
| **Chart** | 一張圖 | 開發人員、業務單位 |
| **Dashboard** | 一頁把多張 Chart 排在一起 | 開發人員、業務單位 |

> 常見誤解：**Dataset 不是資料的複本**。
> 每次開圖表，Superset 都會即時去資料庫查一次。
> 所以資料表沒更新，圖表就不會更新——問題要回頭找 Dagster，不是找 Superset。

### 登入方式

兩套都走 **Keycloak SSO**（realm `postoffice`）：

```
使用者 → https://superset.dai.post.gov.tw
           │ 沒有 session
           ▼
       Keycloak 登入頁（帳密來自公司 LDAP）
           │ 驗證成功
           ▼
       回到 Superset，依 Keycloak 帶回的角色決定看得到什麼
```

D-Track 同理（`https://dtrack.dai.post.gov.tw`），差別是它用 Public client + PKCE。

**兩套系統的權限都統一在 Keycloak 管**——不在各自的網頁上開帳號。
見 [Superset](./日常維運/02_Superset_資料庫連線與權限.md#4-使用者與權限統一在-keycloak-管)
與 [D-Track](./進階調整/10_D-Track_專案_API_Key_與擋門門檻.md#3-權限統一在-keycloak-管)。
